# 视唱练耳 Web App 产品需求文档（PRD）

## 1. 文档信息

| 项目     | 内容                              |
| -------- | --------------------------------- |
| 项目名称 | Oh Your Ear（暂定名）             |
| 文档版本 | v0.3（精简版）                    |
| 目标平台 | Web（响应式：桌面 / 平板 / 手机） |
| 状态     | 待评审                            |

## 2. 产品定位

一款**开箱即用**的浏览器视唱练耳工具：

- 未登录即可使用全部基础练习；
- 登录后解锁学习计划、进度统计、错题本等长期能力；
- 覆盖单音、音程、和弦、旋律、节奏五大训练模块；
- 支持多语言与深色/浅色主题切换；
- 电脑、Pad、手机一致体验。

## 3. 目标用户

- 音乐爱好者
- 艺考/考级学生
- 乐理自学者

## 4. 核心原则

1. **零门槛使用**：打开网页就能练，不强制注册。
2. **实时随机出题**：每道题在浏览器端即时生成，选项带合理干扰。
3. **可重复听辨**：每道题支持无限次重放。
4. **登录增值**：高级数据功能仅对登录用户开放，吸引注册。
5. **全球化与个性化**：支持多语言（至少中英）与深色/浅色主题。

## 5. 功能需求

### 5.0 三种练习模式

产品有三条练习路径，共用同一套题目生成、判分、一轮与小结机制，差别只在**参数从哪来**与**是否留痕**：

| 模式 | 内容 | 权限 | 留痕 |
| --- | --- | --- | --- |
| **随机练习** | 无限题目、实时随机出题，没有轮次、没有目标，随时开始随时停 | 游客可用 | 游客无记录；登录用户的答题计入每日记录 |
| **每日练习** | 按学习计划（每日题数 + 重点模块）生成当天的练习；每天的历史以热力图与连续天数呈现，用来督促坚持。入口在首页第一段，没有独立页面 | 仅登录 | 每日题数、正确率、是否达标、连续天数 |
| **题单模式** | 由官方与用户策展的题单组成，从易到难逐关推进；支持收藏与多个收藏夹 | 仅登录（目录对游客可见） | 每关是否通过、最好成绩；收藏夹 |

对应关系：

- **随机练习** = 无轮次的自由练习（现有实现，改名而来）。
- **每日练习** = 由计划参数驱动的一轮或多轮：进入时算出「今天还差几题」，在重点模块之间轮转，练完一轮给「今日目标进度」，未达标则继续下一个重点模块。
- **题单模式** = 由关卡（参数集）驱动的一轮；关卡之外还允许用户把任意关卡收进自己的收藏夹。

**入口不隐藏**：首页把三条模式都摆出来（今日一段 + 一个 Learn / Random 选项卡，§7.1.4），游客看得到全部三条、也看得到题单目录，点击需要登录的入口时才提示登录（§6 的非阻断提示）。

### 5.0.1 每日练习

- 目标：**每日题数**（默认 20，可设 1–500）与**重点模块**（可多选；不选表示五个模块都算重点）。PRD 早先写的「每日时长」暂不做，时长口径（前台活跃 vs 墙钟）需要单独定义。
- 达标：当天答题数 ≥ 每日题数即算达标（正确率只记录，不作为门槛）。
- 历史：以**热力图**呈现，可用日 / 周 / 月 / 年四个 tab 在同一份每日数据上换倍率（见 §7.1.4）：日档是当天目标的进度条，周/月档是本周/本月的日历，年档是一年的热力图；格子永远是一天，永远按那天自己的目标分档。旁边显示当前与最长连续天数。
- 入口在首页第一段（§7.1.4），没有独立的每日练习页面；题数与重点模块在「我的」设置。
- 连续（streak）沿用现有口径：当天有任意答题即算打卡。

### 5.0.2 题单与收藏

- **题单目录**由服务端提供（官方策展 + 未来用户自建），每个题单含若干关卡，关卡是参数集（音域、选项数量、播放方式、允许音程/和弦/时值 + 题数 + 通过线）。
- **收藏**：任意关卡可收进用户的收藏夹。默认有一个「收藏」收藏夹，用户可以新建多个收藏夹（如「每天热身」「难点」），同一关卡可出现在多个收藏夹中。
- 收藏夹是登录功能，跨设备同步。

### 5.1 练习流程（所有模块通用）

1. 用户进入模块练习页；
2. 点击大播放按钮，系统生成并播放当前题目；
3. 播放结束后展示若干选项；
4. 用户选择答案，立即显示对错与正确答案；
5. 答错可收藏到错题本（登录后）；
6. 点击「下一题」进入新题；
7. 一轮结束后展示成绩小结。

### 5.2 模块一：单音（Single Note）

- 播放一个钢琴音，用户从选项中选出音名。
- 选项范围：C / C# / D / D# … B 共 12 个音名。
- 干扰项从剩余音名中随机抽取，优先音高相近。
- 可配置：音域范围、是否仅白键、选项数量。

### 5.3 模块二：音程（Interval）

- 播放两个音，用户选出音程名称（小二度至纯八度等）。
- 支持旋律音程（先后）与和声音程（同时），可单独或混合练习。
- 可配置：根音固定或随机、播放方式、选项数量。

### 5.4 模块三：和弦（Chord）

- 播放一个和弦，用户判断和弦性质。
- 首期支持：大三、小三、增、减、属七、大七、小七等。
- 和弦默认以原位柱式或分解方式播放。
- 可配置：启用哪些和弦类型、播放方式、是否显示根音提示（P2）。

### 5.5 模块四：旋律（Melody）

- 播放一段 3~8 个音的旋律，用户从候选旋律中选出正确的一条。
- 干扰项为与正确旋律有 1~2 个音差异的变体。
- 可配置：旋律长度、音域、播放速度。

### 5.6 模块五：节奏（Rhythm）

- 播放一段节奏型（打击乐采样，无音高干扰），用户选出对应的时值组合。
- 首期以「选择模式」为主：展示若干节奏图案，选出听到的那个。
- 可配置：拍号（2/4、3/4、4/4）、音符类型集合、小节数、BPM。

### 5.7 播放与重放

- 播放按钮为页面最突出操作，手机端拇指可达。
- 播放中显示状态动画或文案提示。
- 播放完成后可随时重放当前题目，重放不改变题目内容。
- 答错后可单独播放正确答案供对比。

### 5.8 题目生成规则

- 每道题实时随机生成，不依赖预置题库。
- 同一轮内不出现完全相同的题目。
- 干扰项与正确答案不重复，并按模块规则生成（如音程干扰项避免与正确答案度数相同）。

### 5.9 反馈与计分

- 答对：绿色高亮 + 正向反馈。
- 答错：红色高亮所选，绿色标出正确。
- **一轮**默认 10 题，可按关卡配置 5 / 10 / 20（练习模式不设轮次，练到停为止）。
- 一轮结束后进入小结页：正确数、正确率、用时、逐题回顾，可「再来一轮」或返回首页；游客额外提示登录后可查看详细统计。
- 题单模式下小结页同时判关：达到通过线（默认正确率 ≥80%）即解锁下一关并记录本关最好成绩。

### 5.10 登录与高级功能

**登录方式**：**邮箱 + 密码**、Google 登录。**验证码不是一种登录方式** —— 它只出现在两个时刻：注册（这个地址还没有人证明过）与重设密码（没有当前密码可给）。

**验证码负责证明身份，密码是日常进门的那把钥匙。** 这条顺序是这套设计的地基：

- **注册是一次验证码验证，结尾当场设一个密码。** 先填邮箱，收到那封信才建号 —— 否则谁都能抢注别人的邮箱，真正的主人反而注册不了。建号那次顺带就是登录态（地址刚被证明过），紧接着第三步就是「密码 + 再输一次」：登录既然只认密码，注册就必须交出一把，否则新账号第一次回来就得走「忘记密码」绕一圈。
- **密码是直接登录的唯一凭据。** 注册最后一步设它；只登过 Google、还没有密码的账号走**「忘记密码」**（邮箱 → 验证码 → 新密码）—— 这正是验证码留在这条路上的原因。**账号页不再有设/改密码的卡片**：那个页面负责身份、计划与进度，密码不归它管，而忘记密码这条路本来就能拿到一把新的（首次设置不需要旧密码，因为那次会话来自验证码或 Google，地址已证明过）。`PUT /me/password` 仍在被注册最后一步使用。
- **忘记密码是一条自己的路：邮箱 → 验证码 → 新密码**（`POST /auth/password/reset`，未登录时用）。早先的说法是「忘记密码就是先用验证码登录、再去账号页重设」—— 那句话不成立：`PUT /me/password` 在账号已有密码时**要求当前密码**，而忘记密码的定义就是没有当前密码。验证码证明了这个地址属于他，所以这条路径用验证码代替当前密码，其余规则照旧（最短长度、一次性、限流）。成功直接签发会话，少一次在登录页重输。
- **密码策略**：至少 8 个**字符**（不是字节，所以八位中文口令和八位英文一样对待）、至多 72 **字节**（bcrypt 的硬上限 —— 超长直接拒绝，绝不静默截断，否则两个不同的密码能开同一个账号）。不强制大小写数字组合、不强制定期更换、允许粘贴：长度是唯一真正有用的那条，其余只会让人把密码写在便签上（NIST SP 800-63B）。存储用 bcrypt（cost 12），每个密码自带盐。
- **用户名是账号自己的标签，不是身份。** 表里那一列叫 `name`（Google 登录会带上它的名字），用验证码注册的账号是 `NULL`。它能在**任何显示它的地方**改：`PUT /me/name`（trim 后 1–50 个字符，空一律拒绝 —— 空会让「没有名字」多出一种写法；`name` 为 `NULL` 时界面显示一个可点的「添加用户名」空位，所以三件套不会永远缺一件）。改的时候是**乐观更新**：界面先改、被拒再回滚并给一句原因。**不要把它叫成 `username`**：它不是登录标识，重名无所谓，也不是唯一键。
- **不区分"邮箱不存在"和"密码错误"**：两种情况同一个错误、同一个响应时间（地址不存在时也照样算一次哈希再丢掉），否则接口本身就是一个"这个邮箱注册过没有"的查询器。
- **只有一个例外，而且是明知故犯**：注册页要当面告诉读者「这个邮箱已经注册过了」并把他送去登录（§7.1.9），所以有了 `POST /auth/email/check`。它就是一个「谁在这儿注册过」的查询器，代价是真实的：拿到大量邮箱的人可以用它筛出哪些人在这里有账号。缓解只有限流（与发验证码共用同一个按 IP 的额度，所以「不便宜」而**不是**「不可能」）。**想过用布隆过滤器「挡一层」，不行**：布隆只有误报、没有漏报，而这里能容忍的错误方向恰好相反 —— 把没注册的误报成「已注册」，等于把真实的新用户推去登录页（布隆唯一会犯的错，正好是这一侧）。要对误报再查一次库，答案又变精确，对枚举没有任何遮挡。这是产品决定：用一点可枚举性换掉「已有账号的人白等一封信、还被建了个重复账号」这个更常见的糟糕体验。想撤就撤 —— 去掉那个检查即可，接口本身就是为它加的。
- **失败才计数**：按邮箱 15 分钟 5 次（成功的登录不花额度 —— 否则攻击者烧完额度就能把本人锁在门外）。额度花光不影响验证码，那正是注册与找回的入口。
- **一个地址就是一个身份，登录方式只是钥匙。** 所以 Google 登录**不是**另建一个账号，它按顺序认领：①这个 Google 账号以前登过 → 就是那一行，顺便刷新它拥有的字段（名字、头像；空值保留原值）；②这个地址有一个还没绑 Google 的账号 → **把 google_id 挂上去**（Google 说这个地址是它验证过的，而原来那次登录也证明过同一个邮箱，是同一个人走了第二扇门）；③这个地址属于**另一个** Google 账号 → 拒绝（409 并说清楚），**绝不悄悄改绑** —— 那等于把一个人的练习记录交给另一个登录方式。同一邮箱存两个账号是不可能实现的形状：验证码注册是"拿邮箱换账号"，一个地址必须解析到唯一身份，否则今天用 Google 进来看到 A 的错题本、明天用验证码进来看到 B 的空错题本，用户眼里就是数据丢了。
- **验证码邮件是用户读的文案，所以按产品来做，不按"系统通知"来做。** 中英双语（这个产品是双语的，猜错语言等于寄了一封没人看得懂的信）。HTML + 纯文本的 `multipart/alternative`（纯文本在前，客户端显示它认识的最后一段），**验证码是整封信里最大的东西**：等宽字体、32px、加字距，单独躺在一块发丝面板上 —— 读者来就是为了抄六位数字。三条硬规则，都是因为**邮件客户端不是浏览器**：不引任何外部资源（图片、样式表、字体一律不引，客户端会把它们剥掉，结果是一封显示成破框的验证码邮件）；样式**全部内联**（`<style>` 在部分客户端活、部分不活，"部分"就是"在你这台机器上好看、在别处全乱"）；**验证码只放在正文，不进主题**（主题会显示在锁屏上）。深色配色写在 `prefers-color-scheme` 媒体查询里并带 `!important`（内联样式本来会赢过媒体查询），不认这个查询的客户端拿到浅色那套 —— 所以标记里画的是浅色。主题行按 RFC 2047 编码（`=?UTF-8?B?…?=`），正文两段都 base64：裸 UTF-8 在头部不合法，而没声明 `8BITMIME` 的中继有权把它弄乱。
- **只认已验证的 Google 地址**：`oauth2/v2/userinfo` 里那个字段叫 **`verified_email`**（v3/OIDC 才叫 `email_verified`），没有它就是未验证 → 一律拒绝。整条认领规则都建立在"Google 检查过这个地址"上。字段名有单测钉住：绑错名字会让**每一次** Google 登录都被判为未验证，而别的测试全绿。

## 6. 登录策略

| 模式     | 权限                                             | 数据存储                         |
| -------- | ------------------------------------------------ | -------------------------------- |
| 游客     | 全部基础练习、基础设置、单轮成绩                 | 浏览器本地，换设备/清缓存丢失    |
| 登录用户 | 额外解锁学习计划、统计、错题本、同步、打卡、成就 | 云端持久化，本地缓存辅助离线使用 |

- 未登录时不阻断练习流程。
- 在「保存错题」「查看统计」「设置学习计划」等入口用非阻断方式提示登录。
- 登录成功后返回用户原先所在页面。
- **退出登录先弹确认框**：顶栏的退出图标键弹出一个确认框（「要退出登录吗？」/ 取消 / 退出），确认之后才登出。理由不是安全，是**手滑**：顶栏那一排 32px 图标键（语言、主题、退出）形状尺寸完全一样，点错邻居是常事，而其中一个的代价是当场登出。框用浏览器原生的 `<dialog>`（焦点锁、Esc、背景惰性都由平台提供），**Esc、点背景、取消三者都是取消**，焦点默认落在「取消」上 —— 误触的时候落在安全的一侧。
- **顶栏在每个页面完全相同**：`AppHeader` 是同一个组件，任何页面都不隐藏或追加图标键（`/me` 曾经隐藏两个键、页内自带一个退出按钮，于是顶栏在账号页和别处不一样）。退出只有顶栏一处入口。
- **账号页有返回入口**：`/me` 内容区左上角一个 32px 的 `←` 图标键（与顶栏图标键同尺寸同样式），回首页。放在内容区而不是顶栏，正因为顶栏每个页面都要一样。**同一颗键还有三处**：收藏夹与错题本（信息结构上属于账号屏，首页账号卡里那两条只是快捷入口）各有一颗、回 `/me`；关卡目录（从首页模块格子进去）一颗、回 `/`。
- **`/me` 的卡只留字段和数**：计划卡顶部那句「设定每日题数与重点模块；每日练习按它生成当天要练的题。」删掉了 —— 字段名（`每日目标题数`、`重点模块`）自己已经说了这件事。统计卡里「每日题数」这张图与下面那张模块图**用同一套词汇**（同一张卡里两张图不该各说各话）：标题把范围写在里面（`每日题数（近 {{days}} 天）`，天数取自返回的数据）；左侧纵轴标 **0 / 一半 / 峰值**（峰值取这段时间最忙的一天，不四舍五入成 10 或 20 —— 那会把图压矮），绘图区画 0 与 50% 两条发丝网格线、左边一竖底下一横为轴，刻度文字与线对齐；**每一天有题数就把数字印在自己那根柱子上**（贴在柱顶，柱顶上方留 24px 带子，峰值那根也不会写到图外），没答的那天不印数字；柱高按峰值归一，保留「只答一题也有 10% 高度」的下限（否则那是一根头发丝）；鼠标停在任一根柱子上仍是 `日期：N 题`（14 根都有）。原来这张图只有标题和两根柱子：没有刻度、没有单位、题数只在悬停里 —— 14 天里通常只有两三天有柱子，于是它读起来像装饰。「各模块正确率」是**柱状图**：横轴五个模块（**没练过的也占一格**，题数写 `0`、数值写 `—` —— 空着的一格也是信息，而「柱子随用随出现」的图没法跨月比较），纵轴正确率，**发丝线画出 0 / 50% / 100% 三条坐标线**（纵轴刻度文字与线同高，实测对齐误差 ≤1px），柱子**固定宽度 16px**（不用 `flex-1`：等分的柱宽会随模块数量变；两处视口都是这个宽度），柱子之间留出大片空白（桌面 80px、390px 下 37px，绝不并排贴着），数值印在自己那根柱子上方（绘图区上方留了 24px 顶带，100% 时数字也不会写到图外）。**横轴是五条模块色下划线，不写名字**：每个模块一条 2px、与自己的柱同宽、用自己的颜色 —— 与关卡页选项卡选中态那一条是同一种标记（色点在悬停卡片里，不在轴上）。名字是这张图里最宽的东西（英文的 `Single note` 还会折行），字母换成线之后就都不需要了。鼠标停在柱子上会浮出一张**读数卡片**：模块名与色点、正确率、练了多少题、对了多少题 —— `solved` / `correct` / `accuracy` 三个数接口本来就给，不在前端推算；卡片 `pointer-events: none`，不抢柱子的悬停；它一直留在文档里（只用 `opacity` 隐去，不用 `display`），所以读屏软件不必悬停也能读到五条；最外两根的卡片改成贴绘图区边缘对齐，免得窄屏上挂到卡片外面。柱色是 `primary`（浅色近黑 `#0c0a09`、深色近白 `#fafaf9`），与这张卡里其他图表同一个墨色。整张图**占满卡片正文栏**（上限 448px，与上面那张「每日题数」同宽、同左边界），实测绘图区 416×200px（上一版 232×136），390px 下 245×200px 且不横向溢出。原来画的是横向的条、量的是该模块占累计题数的比例，而同一行右边的数字是正确率：一行里两个量、只有其中一个有条，而条画的偏偏不是读者在问的那个。
- **头像图片是唯一走 cookie 的接口**：`<img>` 发不出 `Authorization` 头，所以 `GET /me/avatar` 除了 Bearer 也接受会话 cookie，校验与 `/auth/refresh` 完全一致（类型必须是 `refresh`、且要过吊销名单——登出之后图片也加载不了）。**只放宽这一条路由**，其余接口仍然只认 Bearer。另外上传走的 `POST` / `DELETE` 仍是 Bearer，不受影响。
- **会话**：access token 15 分钟，refresh cookie 7 天（`ACCESS_TOKEN_TTL` / `REFRESH_TOKEN_TTL`）。这 7 天**从登录那一刻算死、不滑动**（`/auth/refresh` 只换 access token），所以每 7 天要重新登录一次 —— 有密码之后这只是一次输入，不再是等一封信。

## 7. 界面与响应式

### 7.1 主要页面

1. **练习枢纽（app 首页，dashboard）**：自上而下两段 —— 今日（身份 + 开始每日训练 + 今日进度 + 热力图；收藏夹与错题本的入口在这个账号卡里）、模块（Learn / Random 选项卡 + 五个模块的网格）；另加登录入口与语言/主题切换。产品价值主张与整屏 hero 属于落地页，不在 app 首页。结构见 §7.1.4。
2. **练习页**：返回、进度、设置、大播放按钮、选项区、下一题。页头徽标在自由练习时写「随机测试」，从关卡进来时**写这一关的名字** —— 关卡模式却挂着「随机测试」是错的。
3. **小结页**：成绩、逐题回顾、再来一轮、返回首页、登录后查看详细统计。
4. **关卡（目录对游客可见）**：按模块分**选项卡**（单音 / 音程 / 和弦 / 旋律 / 节奏，顺序与名字都取自目录数据），一次只看一条链 —— 五个模块竖着堆，要看到第五条得先滚过四条。每关显示已通关 / 当前关 / 未解锁与最好成绩；关卡可收藏，支持多个收藏夹。选项卡**不是**首页 Learn / Random 那种焊接组（一整圈外框 + `divide-x` + 选中态 `bg-surface-strong`）：焊接组的本意是**二选一的开关**（Learn / Random、日历的四个倍率），而这里是**五个平级的兄弟**，并且每个模块在首页都有自己的颜色（`MODULE_SWATCH`，首页档案格子拿它画 3px 色条）。所以每个 tab 是「模块色点（`ModuleSwatch`）+ 名字」，**选中的那个底部一条 2px 该模块颜色的下划线**，其余不画线；**五个 tab 等宽**（`flex-1` 加一个最小宽度，窄屏横向滚动而不折行）—— 英文名长短差得远（`Single note` 比 `Chord` 长得多），点击时整行跟着变宽就是抖动。**当前是哪一档写在 URL 里**（`/levels?module=interval`，取值即目录里的模块名）：所以能从别处链到某一档（首页的模块格子就是这么链的，§7.1.4），切换用 `replace` —— 选项卡不是“去过的地方”，返回键的含义仍是「离开这一页」，不会在试过的档之间逐个回退。非法或缺失的取值退回第一档。**顶部有返回键**：与账号页、收藏夹、错题本同一个 32px `←` 方块，回首页。**游客那一页多一条出路**：只有游客看到的横幅里除了「登录」，还有一句「不想登录？试试随机练习。」，链接指向 `/?mode=random` —— 关卡链要账号，而随机练习**完全不需要**，这是盯着一条锁着的链条的游客最该听见的一句话；句子与链接按老办法交给 `Trans`（标签名 `randomTest`，不是 HTML 空元素名），免得中英各自拼字符串。
5. **我的（登录后）**：学习计划（每日练习设置）、统计、错题本、成就、账号设置。

**独立页面**：登录、注册、重设密码、所有关卡、收藏夹、错题本、我的、练习页、小结页。**登录与注册是两个页面**（§7.1.9），重设密码是第三个。**收藏夹在所有地方都叫 `collections`**（接口 `/me/collections`、路由 `/collections`、翻译命名空间、组件名），中文仍是「收藏夹」—— 之前路由与组件叫 `bookmarks`、文案里说「书签图标」，同一个东西两套叫法，旧地址 `/bookmarks` 保留重定向。**每日练习没有独立页面** —— 它的今日进度、开始按钮、热力图都在首页第一段，设置项在「我的」（见 §5.0.1）。

### 7.1.1 视觉方向：录音室器物感

**字体未就绪时不许换宽度**：自托管的 JetBrains Mono 只声明拉丁范围，字体没到时拉丁字母会按逐字符回退，落到栈里第一个拥有该字符的字体 —— 而那通常是 CJK 字体里的**比例**拉丁字形（雅黑/苹方）。实测每字符 0.9771em 对 JBM 的 0.6000em，**换字体时整行文字宽 63%**，比"抖一下"严重得多。

因此栈里在 JBM 之后**先放等宽回退**（`Consolas`/`Menlo`/`DejaVu Sans Mono`/`Courier New` 的平台面，各用 `@font-face` + `local()` 声明，`size-adjust` 与 `ascent/descent-override` 把度量对齐到 JBM），CJK 字体排在它们后面 —— 逐字符回退会跳过没有中日韩字形的等宽面，中文渲染不受影响。这些回退面限定 JBM 自己的 `unicode-range`，所以它们与 JBM 覆盖的字符集完全一致。

一行文字在字体到达前后宽度差 **0.03px**（改前是 63%）。

界面的词汇取自录音室设备，而不是普通的 SaaS 网页：**硬描边**（1px 发丝线，不用渐变光晕）、**等宽数字**（计数、进度、BPM 一律等宽并右对齐）、**中性舞台上的高饱和模块色**（模块色是识别通道，不是装饰）、**控件看起来能按下去**（播放键、选项键有明确的按下反馈）。

因此明确不用：装饰性渐变光晕与粒子背景、玻璃拟态、鼠标跟随光晕、霓虹色铺满。理由是可读性与性能 —— 模糊背景会降低文字对比度，装饰动画在手机上耗电掉帧，而"什么都发光"等于什么都不突出。

明暗两套主题用同一套词汇：浅色是"工作室日光"，同样的硬描边、象牙白与黑键、同样的模块色，不做"暗色做完再凑合浅色"。

### 7.1.3 hero 里的乐器：钢琴卷帘窗（默认）与柱状图

落地页右栏不放第二个按钮，而放一个**可以玩的乐器** —— 它是产品能力的预告片，也是访客还没注册就愿意停留的理由。左栏是文案与唯一的行动按钮「开始练习」，右栏留给这个物件。

形态演进过三版，结论是**平面 2D**：

| 版本 | 结论 |
| --- | --- |
| 3D 立体柱状图 | 否决。1px 发丝线在 3D 变换里会被栅格化后重采样，断成虚线；详见 memory |
| 2D 柱状图（`?chart=2d`） | 12 个半音各一根**实心**柱子，高度 = 频率，轴截断到 250–500Hz 并标注刻度；点柱子发声。柱子实心、不描边 —— 描边的柱子一眼看去像空盒子，而这张图要传达的正是实心块拼出的轮廓 |
| **钢琴卷帘窗（当前默认）** | 18 行半音（C4–F5）、黑键行加暗底、两小节 4/4 十六分网格（32 步）、可编辑；见下方规格 |

**默认给卷帘窗**：它是这支产品的预告片 —— 访客拖几块音、按一下播放，就知道练耳练习大致是什么样子；柱状图更安静，但它没有「可以动手」这层意思。柱状图保留在 `?chart=2d`。

**编辑规格**（Ableton 式，PRD 层面承诺的交互）：

| 操作 | 行为 |
| --- | --- |
| 单击空白 | 取消选中 |
| 单击音符 | 只选中（不发声、不改动） |
| 双击空白 | 在该格写入音符（默认 1 个十六分） |
| 双击音符 | 删除 |
| 拖音符本体 | 移动（时间 + 音高），吸附到步/行，跨行时试听新音高 |
| 拖音符两端把手 | 改时值，吸附到步；对侧固定不动 |
| 同一时刻多个音 | 允许（和弦）；同一 (step, midi) 不重复 |
| 随机按钮 | 生成一小节随机旋律：混合时值、含 1–3 个和弦、音高在 C4–B4 内 |
| 播放按钮 | 播放整个乐句（两小节，十六分 @80bpm = 6 秒），游标扫过，到末尾自动停 |
| 停止按钮 | 立刻出声即止。整小节是**一次排进音频时钟**的，取消定时器只能停游标、停不掉已排程的音符；所以每次播放走一条独立音量总线，停止 = 摘掉总线 |
| 重置按钮 | 恢复默认乐句（`OPENING_PHRASE`），清掉当前编辑 |
| 频谱 | 走带行里的一格：`AnalyserNode` 接在输出总线上，画成**一条连续折线**（不是一排柱子 —— 折线能看出每个采样点，平滑曲线会骗你峰值在哪），采样点数按宽度算（约每 4px 一个点），横轴对数分组（FFT 的 bin 是线性的，耳朵不是，等宽分组会把一个八度挤进头两根），用 ink 色描 1.5px。静止时它是贴着格底的一条平线 —— 分析仪的零点，离格线还有 4px，不会被误读成结构线。被声音唤醒、声音停下后再画约 0.7 秒自动熄灭 —— 和落地页其它部分一样，闲着不跑 rAF |
| 左侧键盘 | 点任一琴键单独试听该音 |
| **同一音高行不可重叠** | **Ableton 规则**：后写的音符覆盖前一个（截断；完全盖住则替换掉）。不同音高可以自由重叠 —— 那正是和弦 |

**声音**：landing 上的一切声音都来自**三个真钢琴采样**（与应用同一个 Salamander 库的 `C4` / `F♯4` / `C5`，合计 211KB），用 `playbackRate` 移调覆盖 60–77 的全部音高，最坏移调 5 个半音。**不打包采样、也不引入音频引擎** —— 「不带练习引擎」（7.1.2）约束的是包体积与代码，按需取三个文件在约束之内。第一次手势（页面任意 `pointerdown` / `keydown`）才开始下载，早于任何人按下播放。原先那三行三角波合成器**留作兜底**：拿不到 CDN 时仍有声音。理由是这一页唯一的职责就是让人听见产品的声音 —— 合成器听起来像电钢琴，而访客会以为那就是产品的声音。

走带是**一整条发丝压条**，不是一个按键组旁边漂着几样东西：32px 高，一圈外框，内部用分隔线切成格子 —— `播放 | 随机 | 重置 | 频谱 | 读数`。每个格子同高、同样的 `px-3` 内边距、内容垂直居中；频谱在格子里上下各留 4px，柱子不碰分隔线；整条与上方卷帘窗网格**同宽、左右边缘对齐**，与网格间距 8px（与全站间距一致）。键上只有图案，名称放在 `title` 与 `aria-label` 里，供悬停与读屏使用；三个图案一律**描边不填充**（`fill=none` + 1.75 描边）：一组里只要有一个实心块，它就比邻居重。重置键用 `rotate-ccw-square` —— 带棱角的方框加逆时针箭头，既是「回到默认」的方向，也是本仓库的方形语汇。

   实测（460px 栏宽）：整条 460×34，键区 96，频谱格 201，读数格 136，左右边缘与上方网格对齐误差 0.0px。

拖拽预览必须是**吸附后的位置**（跳格），不是跟手浮动 —— 这是"量化"在界面上的可见承诺。

**实现约束**：纯 DOM 2D（无 3D 变换，发丝线恒为 1px 实线）；拖拽期间不进入 React state（只改被拖那一个元素的样式，松手才提交），避免快速指针把渲染器甩在后面；纯逻辑（吸附、夹取、随机生成）独立成 `apps/landing/src/lib/roll.ts` 并由 `node --test` 覆盖。

**默认内容**：打开时不是空的，也不是随机的 —— 是一份 **191 字节、两小节**的 MIDI 文件里的乐句：第一小节是一次带收句的动机，第二小节把同一动机的前半段再起一遍，然后挂在一个长和弦上。（这份文件与库里先前那份 17549 字节的完整转写**不是同一份**：它音级集合里没有 A♭/D♭，更靠近 E♭ 大调 / C 小调那一边。以指定的这份为准。）

把它放进十六分网格，有两处要让步：

| 让步 | 说明 |
| --- | --- |
| **音区** | 源文件落在 **C3–F4**。整体升 12 个半音后，最低音正好落在卷帘窗的 C4、最高音到 **F5** —— 比原来的天花板高 **6 行**，所以音高轴从 12 行变成 **18 行**。音程不变 |
| **第一小节末的收句** | 半拍里四个音（32 分）在十六分网格上放不下，落在格与格之间的那两个被丢掉：收句读作 **F5 → D5** 直接进下一小节，而不是 F5 → E♭5 → D5 → C5 |

其余位置全部落在十六分格上（第一小节 0 / 3 / 6 / 8 / 11 / 14 / 15，第二小节 16 / 19 / 22），时值也按格取整。默认乐句**本身就是 `normalize` 的产物形状** —— 同一音高行上没有任何重叠，与用户在编辑器里拖出来的东西遵守同一条规则（`roll.test.ts` 里有一条断言盯着这件事）。

想换内容只需改 `OPENING_PHRASE` 这个常量。

**停止是真停**：整小节是一次排进音频时钟的，所以取消定时器只能停游标、停不掉已排程的音符；每次播放走一条独立音量总线，停止 = 摘掉总线。见 `memory/2026-09-21-scheduled-audio-needs-a-bus-to-stop.md`。

**刻意不做**：撤销/重做、复制粘贴、缩放、把这段旋律接进练习模块。它目前只是落地页的物件，不是功能入口。

### 7.1.2 两个站点：landing 与 app

前端拆成两个独立应用，同属一个 pnpm workspace，**将来分开部署到不同域名**（landing 在 `xxx.xxx`，app 在 `app.xxx.xxx`）：

| 站点 | 包 | 职责 |
| --- | --- | --- |
| landing | `apps/landing` | 营销落地页：价值主张、整屏 hero、一个「开始练习」入口。不加载任何练习代码 |
| app | `apps/web` | 全部练习功能、进度统计、题单、每日练习、我的 |

为什么拆：落地页与产品各自的演进节奏、设计自由度和加载体积都不一样。落地页被访问的次数远多于 app，它不该为整个练习引擎付出首屏代价；两者合在一起时，任何一方的改动都在牵动另一方。解耦让两边都能各自改。

共享与不共享：

- **共享设计系统**：设计令牌（颜色、明暗两套主题、圆角、字距、模块色）、字体、基础元素样式放在 `packages/shared`，两个站点逐像素同源 —— 营销页不会慢慢长成另一个产品。
- **共享用户偏好**：语言与主题是同一份偏好（父域 cookie + 本地存储），用户在落地页切了深色或英文，进 app 后保持。登录态靠 httpOnly 刷新 cookie 跨子域生效，**不在 URL 里传任何令牌**。
- **不共享**：文案与页面结构。落地页有自己的文案命名空间，避免与产品文案互相牵动；字体文件各自打包（跨域名加载字体要额外配 CORS，不值得）。

- **登录后的回跳**：任何指向练习题或关卡的登录入口都用 `?next=<路径>` 记住用户本来要去哪，登录成功后回到那里，**不掉参数**（`/exercise/interval?level=xx` 回来还是那一关）。`next` 只接受同源路径（以 `/` 开头且不以 `//` 开头），否则是开放重定向。Google 流程也要把 `next` 带过 OAuth 回路（存进 state cookie），否则走 Google 的用户永远落在首页。

**部署形态**：两个前端由 Vercel 托管（`xxx.xxx` 落地页、`app.xxx.xxx` app），Go API 与 Postgres 自托管在 VPS 上。app 的 `/api` 请求由 Vercel 的 rewrite 代理回 VPS，因此**浏览器始终只与 app 域名交互**：刷新 cookie 是 host-only、`SameSite` 保持默认、API 不需要 CORS、OAuth 回调也落在 app 域名上。VPS 上的 Caddy 只为 `api.xxx.xxx` 签证书。

拆分不改变「游客可练基础题」：直接访问 app 域名同样能开始练习，落地页只是入口之一。

### 7.1.4 首页（dashboard）：两段，数据在前

首页按「今天 → 练哪个模块」的顺序自上而下铺两段，三条模式一条也不隐藏；内容仍在 1200px 内框里，栏距 8px。

**会话未知时不猜状态；而且只在对得起等待的时候才画骨架。** 登录态是异步恢复的，在它落地之前「没有账号」和「还不知道」是两回事：`auth-store` 的 `initialized` 为假时，今日卡画成它本来的形状（标签、头像框、按钮行都按真控件的尺寸摆占位块），热力图画成同一个 152px 的空盒子，而不是先渲染游客态再换成账号态——**先闪一下再变**才是读者会注意到的那个跳变。占位块用的是被替换控件的盒子尺寸（头像的 40px、`lg` 按钮的 48px），所以这一屏的高度在加载前后完全一样（实测游客态与登录态今日行高都是 295.5px）。**骨架的出现有两条时间规则**：加载超过 **100ms** 才画（实测本机会话恢复只要 30ms，那么短的一闪是块灰斑，动画连第一帧都走不完）；一旦画出来**至少留 400ms**，否则会出现"闪一下又消失"。脉冲周期也从 2s 改成 **1s、深度 0.4**（`--animate-pulse` 写在共享 tokens 里）：很少有骨架能在屏幕上活满一整个周期，2 秒的淡出读不出"在动"。

**第一段：今日（左右布局）**

- 左侧是身份与动作：登录后显示头像与邮箱（头像三选一见 §5.0.3），下面是**显眼的「开始每日训练」**按钮 —— 按计划算今天还差几题，从今天练得最少的重点模块开一轮（一轮最多 20 题），规则与 15.1 一致。游客在同一位置放登录引导，**登录前后布局不跳动**。**登录后卡片里只有四样东西**：标签（`账号`）、值、动作（开始每日训练 +「我的账号」）、以及底部一条 1px 发丝线之下的**收藏夹与错题本**两个入口。**值是三件套：头像、用户名、邮箱**（`AccountIdentity`；账号页用的是同一个组件、同一个形状，只是尺寸更大）—— 首页账号卡以前只显示头像 + 邮箱、账号页另写一套，同一个账号在两处长得不一样。**前两件就在原地改**：点头像**看大图**（256px，点图片外面或 Esc 关掉 —— 一张图是先看清楚再决定换不换的东西，而文件选择器弹出来就收不回去），点用户名就地变成输入框（回车/失焦保存、Esc 取消）。改名是**乐观更新**：先改界面、请求失败再回滚并给一句原因，而且输入框**立刻收起** —— 「乐观」看不见就等于没有。邮箱只读：它是账号的地址，不是标签。**游客态不是这张卡**：没有账号时头像与身份行都不成立。**标题（`账号`）留着** —— 标题不依赖登录，卡片的两态仍是同一张卡；标题与底部入口之间那一块换成一旬实话、**在这块里竖直居中**（贴顶挂着读起来像卡里少加载了东西）：`Hmm, we don't know you yet — please log in.` / 「嗯……我们还不认识你，请登录。」（干、平，不卖萌，与全站语气一致；全站不用感叹号），而**入口就是这句话里的 `log in`**（下划线链接，与卡片底部那两条入口同一种控件）。**没有单独的登录按钮**：顶栏右上角那个主按钮永远在场，同一屏上再来一个主按钮，其中一个必然是错的形状。底部两个入口保留（它们登录后才有用）。两种状态卡片尺寸一致（高度由右边的热力图决定），所以整页不跳。没有标签（邮箱就是账号），也没有解释句（按钮已经说了它做什么；「今天还差几题」在旁边的热力图上，同一个进度只有一处）。 —— 它们不是又一种练法，而是账号记住的东西，所以跟账号放在一起，不占练习的格子；游客点它们照旧先去登录，登录后回到该页。
- 右侧是今日进度与历史：`已答题数 / 每日题数`（如 `0/20`）、达标标记、一根进度条；下面是热力图。热力图**不复述连续天数**：日历本身就是历史，一行「连续 N 天 · 最长 M 天」是同一件事的第二个说法；连续天数只在 `/me` 的统计卡里出现，那里是它该在的地方。

**热力图是同一张日历的四种倍率**（数据只有一个来源：`GET /me/daily` 的每日桶，页面不再聚合第二套数字）：

| tab | 显示 | 格子 |
| --- | ---- | ---- |
| 日  | 今天 | 一根绿色进度条：`已答 / 目标`，答满即满，超额不再长（与周档同长，铺满整行） |
| 周  | 本周（周一至周日） | 七个格子，一格一天，上方是英文星期缩写 |
| 月  | 本月 | 跟日历一样：从 1 号所在的星期几排起，30 或 31 个格子（二月随年份） |
| 年  | 近一年 | 一列一周的日历热力图，上方月份刻度 |

**日档是一根进度条，周 / 月共用一把尺子**：周 / 月的格子一律 20px、间距 2px（一格 = 一天），所以切 tab 只换形状，不换标尺。**四档都铺满盒子的整个宽度**：日档的条、周档的一行、月档的日历、年档的热力图都在同一个左边缘开始、同一个右边缘结束（月档的七列因此拉宽，格子居中排在各自的列里）；**周档就是月档的一行**，同一个网格只差行数。屏幕窄到放不下时不折行，横向滚动。进度条沿用 app 已有的那一套（底 `surface-strong`），日档用 8px 高（它是整个视图的主角），闯关格子里的 4px；但**日档的填充是日历的达标绿**（`bg-success`）—— 那里「已答」与「达标」是同一句话，条长满时的绿必须就是日历里那天的绿。星期名 12px（跟它标注的 20px 格子相称），年档的月份刻度 10px。**年 是唯一的第二个倍率**：371 天要塞进一张卡，格子随卡片宽度流式变化（桌面上 8px，宽卡最多 10px，窄到 8px 以下宁可横向滚动也不缩到看不清）。**四个视图的左边缘一律对齐**：年视图不再占一列 32px 的星期名竖栏，星期刻度只以横向形式出现在周 / 月档，月份刻度只出现在年档。

**四档共用一个固定高度的盒子** —— 来回切 tab 不许让卡片变高变矮（月档六行时最高，就按它的高度定盒，现在约 152px）。**日档就是今日进度本身**：右侧面板不再另画一根进度条和另一个数字，同一个进度只有一处。日档是一根条，所以它的图例说的是条的两截：「已答 / 未答」；其余三档的方块是「天」。

**今天那格用形状区分，不用描边**：描边（即使降到 `muted`）是整张日历上唯一一条线，抢眼，而且让形状闲着。今天那格旋转 45 度成菱形并缩到 0.75 倍 —— 对角顶点仍落在 22px 格距的空隙里，不碰邻居；年档 8px 的格子上菱形依然分得清，而描边在那个尺寸只是一点污渍。颜色继续说「那天达标了吗」，形状说「这是今天」，两件事分开画，图例里给这个形状一个位置。

**每个日历格子永远按那天自己的目标分档**（达标 / 练过但未达标 / 未练）。周月年没有"相对强度"这一说 —— 目标只以天为单位存在，格子里的颜色说的还是"那天我做到了吗"。年视图现在只有一两格宽的年头（历史不满两年），随使用增长。

**头像**（§5.0.3）：登录后的账号卡与 `/me` 都显示头像，来源三选一 —— **用户自己上传的 > 登录方式给的（Google 的 `picture`）> 我们生成的像素头像**。没有自己头像的账号用**按账号 id 派生的 identicon**：5×5 左右镜像方块，**颜色也来自同一个 hash**（一个色相、深浅两档，跟 GitHub 看齐）—— 每个账号不同，同一个账号永远同一张，且不落库、不占接口。颜色直接写在元素上，**不随明暗主题切换**：头像不该因为主题换个意思。**不用人形剪影**（那会踩恐怖谷）。**点头像打开的是预览，不是文件选择器**：放大到 256px，交给平台的模态（`<dialog>` + `showModal()` —— 顶层、背景层、Esc、焦点都归平台），点图片外面或 Esc 关掉。**更换头像有它自己的按钮**，就在头像下面那行说明上（`auth.avatarUpload`）：那行本来就在，原来放的是「移除」，而移除既不常走又不可逆，却占着唯一的键。两颗都是真按钮，键盘可聚焦、回车可开。上传在**浏览器里**居中裁方、缩到 256×256 JPEG 再传（服务端只验格式与体积，不缩放）：PNG / JPEG，16×16 到 1024×1024，≤ 512KB，字节说了才算（不看请求的 content-type）。**浏览器在上传前先筛一遍**：格式不是 PNG/JPEG、超过 512KB、短边小于 16、长宽比超过 3:1、以及解码不出来的文件，都当场拒绝并各自说明原因，请求根本不发出去——服务端仍然是最终判据，只是不再由它第一个发现。头像下面那行说明**恒定占位**，拒绝的话不会把页面推下去。上传的图存在 `user_avatars` 表里（一张 ≤ 512KB，跟着 `pg_dump` 备份走，不引入对象存储）；**界面上不再有移除的键**（`DELETE /me/avatar` 与「退回登录方式给的头像或像素默认」这套行为留在服务端）。

**第二段：模块（Learn / Random，选项卡）** —— 两段的格子内容完全同构（都是那五个模块），只是一个带进度条一个不带，所以合并成**一个选项卡 + 一个五格网格**（宽屏五列，手机两列）：选项卡切换的是「点下去会发生什么」，不是换一批模块。**Learn 档的格子去 `/levels?module=<模块>`** —— 对应那条链的选项卡，而不是直接进「下一关」：挑哪一关是读者的决定，而链条那一页就是做这个决定的地方（格子上的进度条仍然告诉你走到哪了）。**Random 档的格子仍然去 `/exercise/<模块>`**，那个选项卡的意思本来就是「点了就自由练习」。关卡页对游客开放，所以这两档的格子都不拦登录。选项卡沿用热力图四个 tab 那套压条词汇（一整圈外框 + `divide-x`，选中态 `bg-surface-strong`），两个 h2 因此由它取代，不再重复。**选项卡那一行右侧放题单入口**（`/levels`，带下划线以区别于选项卡）：它若挂在网格下面，就会只在 Learn 档出现，切 tab 时页高抖动 —— 两档的格子高度、页面高度都必须一样。**哪一档写在 URL 里**（`/?mode=learn|random`，缺失或非法值退回 Learn）：与关卡页的模块选项卡同一套做法，可分享、可从别处链过来 —— 关卡页那句「不想登录？试试随机练习」就是链到 `?mode=random`；切换用 `replace`（选项卡不是去过的地方）。

- **Learn**：五格都是模块的关链，每格一根**闯关进度条**（已通关数 / 总关卡数）加一个 `0/4`。
- **Random**：同样五格，**不带进度条** —— 随机练习无尽、不留进度，没有可显示的量。格子里只有模块名，不再写一句「这个模块是什么」。

**未登录**：进度条显示 0、热力图全部「未练」，不显示假数据也不显示骨架屏；点需要登录的入口才触发非阻断提示，登录后回到原本要去的页面（§6）。

### 7.1.5 落地页第二屏：免费与开源

第一屏是整屏 hero，第二屏回答访客一定会问的那一个问题：**这东西要花多少钱**。答案是三句话，不摊开成价格表，也不做成功能对比矩阵。

| 主张 | 依据（写具体的那一句，不写形容词） |
| --- | --- |
| 开源 | 代码在 GitHub 上，Apache-2.0，可以自己跑一份 |
| 免费 | 五组练习不用付钱，账号只是为了记住你练到哪 |
| 没有额外费用 | 没有订阅、没有解锁费、没有要单独买的关卡 |

**语气**：这一屏是对着「把练耳做成订阅生意」这个做法开火，不是对着某个产品 —— **不点名任何具体 App**，也不写形容词（"最专业""最好的"），只写能核对的事实。三句主张本身是事实，攻击性放在标题与每句的落点里。

**为什么是卡片**：这一屏试过三种排版。带发丝线的表格行读起来像待填的设置表单（线是"字段"的语言）；去掉线的两列词条又太像术语表，五行短句堆在一起没有分量。卡片是第三种：一格一件事，正好是 DESIGN 里"棋盘"那个词的用途，一屏就说得完。

**这一段有编号**：hero 是封面，不编号；它之后的每一屏都是同一本说明书里的一节，标题上方写自己是第几节 —— `01`，24px 等宽数字、`text-muted`、**不加分隔线**（加线会看着像一条走带条，像 UI 控件而不像章节号）。以后加屏继续 02、03。

**底色**：编号屏的底色**与相邻那一屏交替**（hero `--canvas` → 01 `--canvas-soft` → 02 `--canvas` …），用的是 tokens 里"页面内更浅的一块" `--canvas-soft`。目的只是让相邻两屏不看起来像同一块，别让两屏连成一片。**不用底纹图案** —— 密网格会跟正文和格子里的发丝线打架。

**这一屏不放图案**（记录一次否掉的方案）：试过四种 —— 点阵读数 `¥0`、横划掉的 `¥`、归零的价位电平表、圆圈斜杠 `¥`（1.75px 描边）。结论是都不如不加：下面三行加一块不同的底色已经把话说完了，再摆一个符号会把标题挤窄、把这一屏变成"左文右图"的配图区，而那个符号说的又是三格已经说过的事。**留白就是这一屏的构图**，不要再给它配图。

**写法**：一整圈外框 + `divide-x` 切成三个同高的格 —— 就是页头键组与走带条用的那套「压条 / 焊接组」词汇，**不是三张各带边框的卡片**。这一屏**不再放第二个动作按钮**：一屏一个动作是不变量，动作留在第一屏的「Practice」。**不动用模块色** —— 五个模块色是练习模块的身份，不是这里的分区装饰。

**footer 属于整页的末尾**：内容不足一屏时贴视口底，超过一屏时跟在内容之后。品牌、源码、许可证各只有一处，第二屏不再重复一遍。

### 7.1.6 hero 的副标题：分两段

hero 的副标题分两段，**先列功能，再给一句人话**：

1. **功能行**：五个模块的名字，每个前面带自己的模块色块（`--swatch-*`）。这是落地页唯一使用模块色的地方 —— 颜色在这里就是身份（DESIGN §2），不是装饰；顺序与 app 首页的五个网格一致。
2. **一句文案**：**反问句**，比陈述更刺一点。写给**已经在做音乐但听不出来的人** —— producer、乐手 —— 不是写给"想在 KTV 不出丑的人"。当前这句：「弹了10年琴，还是靠肌肉记忆？」（`10 years of playing, and it's still muscle memory?`）

副标题不再说"随时开始"（大标题已经是「随时随地练耳。」），也不再说 KTV（那是唱歌视角，与这一版的落点不符）。「不用注册就能练」从 hero 挪到第二屏的「免费」格里 —— 页面上仍然只说一次。

### 7.1.7 第三屏（02）：账号是用来做什么的

上一屏的最后一句是「也不用注册」，访客紧接着会问：那注册是干嘛的。这一屏就回答这一句，回答完就停。

- 标题：「账号只是用来记住这些。」（`An account is only here to remember these.`）—— 用「只是」划范围，**不重复上一屏已经说过的"不用注册也能练"**。
- 正文是五张**卡片**（名称 + 一句说明），排布沿用 app 首页棋盘的写法：`grid gap-2`、一格一个 1px 发丝外框、`bg-surface` 底色。**卡片上方不放 3px 色块** —— 那一条在 app 里是模块色（练习模块的身份），这五项不是五个模块，内容按使用顺序：**关卡模式 / 每日计划 / 进度记录 / 错题本 / 收藏夹**。每一条都必须是真的账号能力，不写"即将推出"。一行说明控制在一句以内 —— 这一屏是解释"账号做什么"，不是功能清单。
- 词条下一行小字说明代价：「不登录的话，成绩只留到这次会话结束。」—— 这句是**新信息**（游客的成绩只存在本次会话），不是上一屏的重复；"别担心"由**范围**（就这么五条）传达，不由一句安慰话传达。
- **通栏齐左**，与 hero、01 同一套对齐。试过整块靠右（解答上一屏的问题"从另一边出声"），但把一行行短卡片推到右边之后，左半边空着、卡片之间的节奏也散了，读起来不如齐左顺。
- 不在这一屏放按钮：注册入口仍然是顶栏那一个，动作不变。

### 7.1.8 第四屏（03）：需求与 bug 的反馈渠道

这一屏只回答一句话：有问题、想要功能，去哪儿说。

- 编号 `03`，底色与相邻屏交替（`--canvas-soft`），骨架与 01、02 相同：编号 → 标题 → 内容。
- 标题：「有 bug、有需求，直接找我。」（`Bugs and feature requests, straight to me.`）
- 内容是**一个邮件地址**：`me@hypervapor.org`，`mailto:` 链接，等宽 20/28px、下划线 —— 这一屏的"动作"就是它。**不做表单**：表单需要后端，而落地页刻意不带后端（PRD 7.1.2）。也**不做填充按钮**：一屏一个动作，那个位置留给 hero 的「Practice」，邮箱是链接不是按钮。
- 地址下面一行次要入口：「也可以在 GitHub 开一个 issue。」整句一个链接指向 `…/issues/new` —— **不把一句话拆在链接两边**，拆了翻译就会散。
- **宽屏右栏是一个彩蛋，不是一份清单**：一块**读数面板**（`声音检查` 标题 / 「听两个音」按钮 / 揭晓读数与那句话），按下去用落地页自己的 Web Audio 放出相差半音的两个音，随后才揭晓它们是什么（`C5 → C♯5 · 小二度`），最后一句是「没响？那是 bug。」。谁都没预先解释这个按钮 —— 揭晓本身就是彩蛋。

  **面板的秩序感是必须的**：一个按钮单独悬在右半边没有归属。所以它跟页头键组、走带条用同一个对象 —— 一整圈 `--hairline-strong` 外框，内部用同样的线切成格：标题一格、控制一格（整格是按钮，左对齐，悬停垫一层 `surface-strong`，与 app 的选项键同一种反馈）、揭晓之后再长出一格。这样它读起来是一台有铭牌、有按键、有读数的设备，而不是一个漂浮的控件。

  **这一屏拒绝细碎文本。** 第一版右栏是两组各三条的"报 bug 带上这些 / 想要的功能"，六行小字，读起来像填表须知，把这一屏从"渠道"降级成了"客服说明"。彩蛋同时干掉了这个问题和另一个更实际的问题：落地页是每个访客都必经的一屏，**在这里报告"没声音"的人，本来不会去仓库提 issue** —— 微信内置浏览器没声音（#88）那类问题正是这样才收得到。

- 另有一个隐藏彩蛋：控制台里印一行 `bugs and feature requests → me@hypervapor.org`（英文，面向开发者，与 PRD 7.5 的机器可见层一致）。
- 邮箱只在这一屏出现；页脚不放它（页脚是导航与小字，反馈渠道是一个屏）。

### 7.1.9 账号三屏（`/login`、`/signup`、`/reset`）

**卡片左上角是一颗返回键，不是铭牌。** 早先这里放的是落地页与顶栏那颗连体 nameplate（三个页面画的是同一块铭牌），后来去掉了：这是产品内部的表单页，不需要再自我介绍一次，而一行 wordmark 在只有一个输入框的卡片上是纯占地方。位置留给了 32px 的 `←` 图标键 —— 与 `/me`、收藏夹、错题本那颗同尺寸同样式（`iconKey`，`-ml-2` 让它的笔画落在卡片的文字边缘上），点击回首页。**卡片下方的「返回首页」文字链接一并删掉**：同一个动作不需要两种控件，而图标键占的高度是那行文字的一半。

**三张卡片是同一个组件**（`AuthCard`）：同一块铭牌、同一个标题位置、同一道发丝线、同一个 Google 按钮、页面下方同一条“去另一边”的链接与「返回首页」。只有表单不同 —— 做成一个组件，是为了它们不会漂成三张长得差不多的卡片。**标题下面那句说明是可选的，只在页面自己没说的时候才写** —— 现在只剩注册最后一步在用（「设一个密码，以后用它登录。」，那是登录规则的转折点）。删掉的三句都是自解释的：「用密码登录，也可以直接用 Google。」「首次登录即自动创建账号。」「验证码会发到这个邮箱，验证之后就能设置新密码。」。

- **登录与注册是两页，不是一页上的两档。** 注册确实靠验证码完成（§5.10），但“我要进来”和“我要建号”是两个问题，问在同一屏上就要用一档控件去解释它们的关系。现在：`/login` 只负责进来，注册在 `/signup`。
- **登录只有一条路：邮箱 + 密码**（外加 Google）。没有验证码输入框，也没有「用验证码 / 用密码」选项卡。早先那版把验证码也做成一种登录方式，代价是每进一次门都要等一封信；**验证码真正被需要的地方只有两处：注册（地址还没被证明过）与重设密码（没有当前密码可给）**，登录不属于它们。这条改动同时带走了「两种方式必须等高」那个约束 —— 单列表单，没有两档可切，自然也没有高度要对齐。
- **没设过密码的账号从「忘记密码」进来**（验证码注册的、或只用 Google 登过的）：邮箱 → 验证码 → 设一个新密码，设完就是登录状态。同一个入口对“记得密码但忘了”的人也是这条路，所以两件事故意不分家。
- **两页都能 Google、互相能跳**：`/login` 底部「没有账户？去注册」，`/signup` / `/reset` 底部「已有账户？去登录」，三页的 Google 入口同一个。**跳转带 `next`**（`signupPath` / `loginPath` / `resetPath`）：从练习页被拦到登录页的人，绕一圈去注册再回来，仍然落在原来要去的地方。
- **注册是渐进的：一步只问一个问题，一共三步。** ①**只要邮箱**：一个输入框，**提交箭头长在输入框里**（与验证码那一行同一个焊接组，右侧 `→`）。箭头**只在输入框里是一个合法邮箱格式时才出现** —— 判据就是 `type="email"` 自己的 validity，不为「邮箱长什么样」再养一套正则；没东西可提交的时候，按钮就不该在那里。**重设密码的第一步用的是同一个组件**（`EmailArrow`），不是另写一份长得像的：两步问的是同一件事、做的是同一件事。②**只要验证码**（连着发送/重发按钮），写着验证码发到了哪个地址，可「换个邮箱」退回第一步。③**密码 + 再输一次**：登录既然只认密码，注册就得交出这一把，否则新账号第一次回来只能走「忘记密码」。Google 全程在场 —— 渐进式页面最怕的是“另一条路看不见了”。
- **提交邮箱时先问一句「这个邮箱注册过了吗」**（`POST /auth/email/check`）：注册过就不进第二步，就地提示并引导去登录（带 `next`，并把已填的地址带过去）。这是全产品唯一一处回答这个问题的接口 —— 代价写在 §5.10。
- **第几步写在 URL 里**（`/signup?email=…`）：这不是炫技，是一步只问一个问题换来的代价 —— 如果第二步只是组件内的状态，第 2 步刷新就回到第 1 步，而重发受 60 秒冷却限制，手里明明有验证码却卡在第 1 步。实测刷新后仍在第二步。
- **忘记密码的入口在密码字段下方**，走 `/reset`：邮箱 → 验证码 + 新密码 + 再输一次 → 直接登录。**新密码要输两遍**（与注册最后一步一致）：改密码是低频、易输错的动作，没有确认框就等着有人把自己锁在门外。这条路径用 `POST /auth/password/reset`，理由见 §5.10。
- 提交按钮满宽，下面一条发丝线，再下面是 Google。
- **注册与重设页上，验证码输入框和它的发送按钮是同一个焊接组**（`iconGroup` 的规则，DESIGN §2）：一圈 `hairline-strong` 外框套住两者，中间一条发丝内线，**没有间隙、也没有第二条边框**。两者因此**等高** —— `items-stretch` 不给按钮自己的高度，高度由输入框定；改成 `gap-2` 的两个独立控件时，输入框 45px、按钮 40px，差 5px，一眼看得出来。输入框自己的边框与焦点边框交给外框：`focus-within:border-ink`（不然焦点落进输入框就完全没有可见指示了）。发送按钮用 `ghost`（焊接组里的控件不该自带边框，悬停垫一层 `surface-strong`，与顶栏的键同一种反馈），60 秒冷却期间自己读秒。
- **Google 入口读作「Continue with Google」，前面带 Google 的官方四色标记。** 品牌标记是**第二处允许出现的非调色板颜色**（第一处是头像，§5.0.3）：它必须一眼认出来，单色的 G 读起来只是"某个图标"。四个 `fill` 用品牌自己的值（`#4285F4` / `#34A853` / `#FBBC05` / `#EA4335`），不写成 token。**重设密码页没有这一个**（`withGoogle={false}`）：这一页的前提就是"我进不去"，能用 Google 进来的人不需要重设密码，而"换个方式登录"就是卡片底部那条链接。分隔线与按钮是同一段，一起走 —— 关掉之后不留下一条悬在卡片底部的线。
- **nameplate 用 `inline-flex`，不是 `flex`。** 块级 flex 会撑满所在容器：在顶栏里它是 flex item 所以看不出来，放进卡片就变成套在 32px 标记外面的 382px 空框。
- **错误信息内联在它所属字段的那一行，那一行始终占位。** `Field` 的 `error` 与 `hint` 共用一行（`error ?? hint`），只要调用方传了字符串就渲染，且行高固定 18px —— 于是卡片在「什么都没说 / 有提示 / 有错误」下**高度完全相同**。改之前错误是表单中间的一个独立段落，一出现就把卡片撑高约 40px，而卡片外面是居中布局，于是整块内容上下同时弹一下。错误落在**哪个字段**由失败的动作决定：注册页发码失败落在邮箱那一行（地址不合法 / 太频繁），登录页密码错落在密码那一行，重设页上验证码错落在验证码那行、密码不合法落在新密码那行。**改输入即清掉自己的错误**，错误不该赖着。

  **这一行必须能一行放下**，所以消息只能是短句。原来的验证码提示带着一句"若服务端未配置邮件投递，验证码会打印在服务端日志里"—— 那是 `docs/deploy.md` 的知识（它是开发期的事实，不是用户要读的东西），留在界面里就会换行，把"高度恒定"这件事破掉。**能一行放下是这条规则的一部分，不是巧合。**
### 7.5 搜索与分享元数据

落地页 `xxx.xxx` 是**唯一需要被搜索引擎收录**的站点；app 站点 `app.xxx.xxx` 反过来要 `noindex` —— 它是登录后才完整的应用界面，与营销页构成重复内容，被收录没有收益。

| 项目 | 要求 |
| --- | --- |
| favicon | 品牌耳朵标记 + 垫底色，**跟随系统深浅色**切换（浅色：黑图案白底；深色：白图案黑底） |
| 分享卡片（OG/Twitter） | 1200×630，品牌调性，绝对 URL —— 社交平台不解析相对路径 |
| 分享卡源文件 | `apps/landing/og-card.html`，渲染命令写在文件注释里。**模板必须进仓库**：第一版卡片的模板没提交，改一次文案就得靠量像素盲猜重画 |
| 语言 | 机器可见层一律英文：title / description / OG / Twitter / JSON-LD / `robots.txt` / `llms.txt` / 分享卡上的文字。读者看到的内容仍跟随语言偏好，`<html lang>` 在 i18n 初始化后由 `languageChanged` 改写 |
| 元数据 | title / description（长度控制在搜索结果不被截断）、`canonical`、Open Graph、Twitter `summary_large_image`、深浅两套 `theme-color`、JSON-LD（软件类结构化数据） |
| robots.txt | 允许抓取落地页，指向 `sitemap.xml` |
| sitemap.xml | 至少包含落地页 |
| llms.txt | 给大模型的站点说明：产品是什么、能做什么、关键页面，遵循 llmstxt.org 格式 |

两个站点的品牌标记保持一致。落地页当前是客户端渲染的 SPA，搜索引擎能执行 JS，但**首屏 HTML 里没有正文** —— 要做到极致需要预渲染/SSG，单列为待办。

### 7.6 仓库的检索面（GitHub）

GitHub 的仓库搜索主要吃四样东西：**描述**、**topics**、**README**、仓库名。前两样是元数据，权重最高；README 决定点进来的人留不留下 —— 所以它是**营销页，不是技术文档**，技术细节交给 `docs/tech-spec.md`。

| 项目 | 要求 |
| --- | --- |
| 描述 | 一句话，含主要检索词（ear training / interval / chord / melody / rhythm），并说清免费与开源 |
| Homepage | 必须是**带 scheme 的绝对 URL**（`https://ohyourear.com`）—— 少了 `https://` 就不会被渲染成可点链接 |
| Topics | 不超过 20 个，覆盖"练耳/乐理"与实现栈两组词 |
| README | 营销风格：开篇是**落地页左上角那个 nameplate**、一句 tagline、一个真能点的入口；卖点讲人话（练什么、访客能做什么、登录多什么、多语言多主题），技术栈压成一行 |
| README 里的品牌图 | `.github/assets/nameplate-{light,dark}.png`，源文件 `apps/landing/nameplate.html`（渲染命令写在文件注释里，与分享卡同一套路）。用 `<picture>` 按 `prefers-color-scheme` 二选一：图案是 ink 色，浅色下近黑、深色下近白，一张图盖不住两套 |
| 标签 | 除 GitHub 默认那套之外按**区域**补：landing / app / api / audio / ui / i18n / infra / seo / performance / security / polish |

README 写**英文**：仓库页与 title / description / llms.txt 同属机器可见层；产品本身仍然双语。

### 7.2 响应式断点

| 断点               | 布局要点                                             |
| ------------------ | ---------------------------------------------------- |
| ≥1024px（桌面）    | 内容居中最大宽度 1200px（与顶栏同一容器，左右边缘对齐），模块卡片 3 列，选项 2~3 列 |
| 768–1023px（平板） | 模块卡片 2 列，选项 2 列                             |
| <768px（手机）     | 单列，底部固定主操作按钮，单手可达                   |

首页（dashboard）的额外规则：模块网格在手机保持**两列**（5 格排成 2+2+1）、宽屏五列，闯关格子的进度条不被挤掉；第一段的左右布局在手机**上下堆叠**（身份与开始按钮在上）；热力图横向滚动，不缩格。

**内容宽度不随滚动条变化。** 两个站点在 `html` 上写 `scrollbar-gutter: stable`。落地页永远滚动，app 首页正好一屏，于是同一个 1200px 居中盒在两边差半个滚动条的宽度（Windows 上约 7.5px），切换时会看到横移。实测（1440 视口）：两边的顶栏内框都是 `x=120 w=1200`，但文档高度一个是 900、一个是 3526 —— 容器一致，差别只在滚动条。

**落地页：每一屏正好一屏。** hero 与后面每一屏都是 `min-h-[calc(100svh-65px)]`，所以内容装得下时三屏等高、各占一个视口，滚动是一屏一屏地翻。这是**内容预算**问题而不是 CSS 问题：字号与留白按最窄档定，改文案或加行前先量 375×667（每屏 602px）与 360×640（每屏 575px）。视口高 ≤700px 时再收一档（留白 48px、卷帘窗 160px，见 DESIGN §9）。

**装不下时它自己变高，绝不裁。** 不用 `overflow-hidden`，也不做屏内滚动 —— 320×568 这种一屏只有 503px 的老设备上，屏会变高，宁可滚动节奏不齐，也不把文字切掉。

### 7.3 无障碍

- 支持键盘操作（空格播放、数字键选选项）。
- 对错反馈同时用颜色与图标/文字表达。
- 颜色对比度满足 WCAG AA。
