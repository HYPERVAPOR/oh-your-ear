# 探针过了，用户一上手就撞到

退出登录加了确认框。探针验了：`:modal=true`、384×139 居中、焦点落在「取消」、Esc / 点背景 / 取消都能关且不登出、确认之后路径回到 `/`、`/me` 链接消失、顶栏键组变回游客态。

全绿。然后用户点了一下：**确认之后，对话框还留在屏幕上。**

原因：`handleLogout` 只做登出和跳转，从没把 `confirmingLogout` 置回 `false`；`onConfirm` 就是它，所以没人关闭这个框。`/me` 上碰巧看不出来（`navigate('/')` 把整页卸载，框跟着走了），但顶栏是**每一页都挂着的**，从首页确认登出之后框就留在原地。

## 探针错在哪

我断言了**路径**和**顶栏键组** —— 都是"后端/路由层面"的证据，也是我实现时脑子里想的东西。而用户看到的是**屏幕中间那个框还在不在**。两个字就写完的断言，我一个都没写：

```js
// 我写的
log.push(`确认后 路径 ${pathname}  键组 ${JSON.stringify(keys)}`)
// 该写的
log.push(`确认后 框还开着吗：${!!openDialog()}`)
```

**探针的断言集合要按"用户能看见什么"来列，不按"我改了什么"来列。** 改的是状态机，就该断言那个状态机的可见后果；而一个 `open` 标志的后果就是"框在不在"。

## 修法顺带改对了契约

不是给调用方补一行 `setConfirmingLogout(false)`（下一个调用方还会忘），而是把关闭收成一个入口：

- `onDismiss()` —— Esc、点背景、点取消、**以及确认之后**，所有"这个问题结束了"的路径都走它。
- `onConfirm()` —— 只负责干活。

**确认框的确认必然意味着问题结束**，所以组件自己保证关闭，调用方不需要记得。

## 下次

写完探针，回头看一眼这次改动的**可见后果清单**（框开没开、按钮变没变、卡片高没高），每条都写一个断言。少写路径，多写"用户眼睛能看见的东西"。
