# 无作用的请求：先说，别默默做

用户让我把落地页左上角的 logo 与 title 做成可点击的。我照做了，用户随后撤回：

> 还是别 可点击了 我想了想 好像有点多此一举 本来就在这个页面 点了也不会有变化 **你怎么不阻止我 忘了 ponytail 了吗**

**这个念头我确实闪过** —— 分析的当时就记着"落地页点 logo 就是回它自己，没意义，但无害"，然后一句没说就做了。这就是问题所在：不是没想到，是想到了没说。

## 规则

ponytail 阶梯第 1 级是"这件事需要存在吗"。如果一个请求：

- **是 no-op**（本就在那一页，点了不会有任何变化）
- 或**与既有规则的目的相悖**（我当时的理由是"app 与落地页应该一样"，但那条规则管的是**外观一致**，不管某一边该不该有这个交互）

→ **先说一句再做，或者先问。** 一行话的成本，远低于做完再撤。

用户明确表达过：**希望被拦**。"你怎么不阻止我"是抱怨我没说，不是抱怨我做了。
