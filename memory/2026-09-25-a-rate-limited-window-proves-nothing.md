# 限额窗口里的状态不能当判据

## 事情

目标：让推 `dev` 不创建 Vercel 部署，靠 `git.deploymentEnabled: {dev: false}`。配置先写在 `apps/web/vercel.json` 与 `apps/landing/vercel.json`。

实验：在 `dev` 上推一个只存在于 dev 的提交，然后看该提交有没有 Vercel 状态。
结果：没有状态。于是得出结论「必须放仓库根，放子项目里会静默失效」，写进文档、PR 描述和 issue。

把配置挪到仓库根，再推一个提交——**同一个实验，这次挂着两条 `Deployment rate limited`**。也就是说之前那次「没有状态」可能只是状态还没到（90 秒 vs 100 秒），或者别的时序差异。

## 为什么会这样

额度耗尽期间 Vercel 给每个提交都挂那条状态，两种完全不同的情况在这里**长得一样**：

- 配置生效 → 没有创建部署 → 没有状态
- 配置无效 → 创建了部署 → 被额度挡下 → 有状态

这个窗口里不存在能区分两者的观测量。

## 教训

- **一次观察 + 一个可能的解释 ≠ 证据**，尤其当另一个解释同样成立时（这里是「部署根本没创建」vs「状态还没到」）。
- 判断「某件事有没有发生」要看**唯一的真相来源**：这里是 Vercel 面板的部署列表，不是 CI 状态、不是某个提交上的小标记。
- 结论写进文档之前，先问「如果一个小时后结果相反，我会怎么知道」。这次没问，结果是文档、PR、issue 里都写了一个错的结论，还要人工撤销。
- 相关：`git.deploymentEnabled` 现在写在三处（仓库根 + 两个子项目），因为「到底读哪一份」在这个窗口里验不出来。同值配置重复写的成本是零，猜错的成本是额度。

## 事后：我在同一天又栽了一次（2026-09-25 晚）

写这条记忆之后，我**又一次**用「额度耗尽期间没有 Vercel 状态」去证明分支规则生效，并向用户报告了「dev 推送不创建部署」。额度恢复后一查 Vercel API：`dev`、`feat/*`、`fix/*` 全都在建部署（当天 111 条记录）。

补一条更准确的机制：**额度耗尽时 Vercel 根本不创建部署记录，也不发 GitHub 状态** —— 所以「没有状态」不是「被跳过」，而是「什么都没发生」。两种原因在额度耗尽期间外观完全一致，这就是为什么那段时间做不了任何判断。要判断规则，必须**在额度可用时**推一个分支、然后去 Vercel API 里数部署记录（`/v6/deployments?projectId=…`），而不是看 GitHub 上有没有状态。
