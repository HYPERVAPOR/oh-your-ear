# 口头需求不落盘 = 需求不存在（题单模式的教训）

## 背景

做 UI 重设计时用户问「题单有了吗？我应该说过分两个模式：练习模式（无限随机）和题单模式（从易到难打怪升级，登录独有）」。

## 经过

全仓检索 `题单|关卡|难度|升级|打怪|闯关|lesson|level|progression`：**PRD、开发计划、memory、代码里零命中**。这条需求只存在于对话里，从未落盘。

后果是连锁的：我此前每一轮"对着 PRD 逐条核缺口"都以 PRD 为基准，**基准里没有的东西查不出来**。于是登录体系、统计、错题本、打卡、成就、UI 重设计全都做完了，题单模式一次都没被算进工作量 —— 而它其实是产品的一半（登录用户的核心增值）。

更糟的是这不是孤例风险：PRD 里也没有"一轮 5/10/20 题 + 小结页"的落地路径（我提过缺口，但没上升成里程碑），直到题单模式逼着要它才做。

## 结论

1. **口头需求当场落盘**：任何用户口述的功能，先写进 `docs/prd.md`（需求 + 页面 + 验收）与 `docs/dev-plan.md`（里程碑 + 条目），再谈实现。这次补上了：PRD 5.0 两种模式、5.9 一轮与小结（含判关规则）、5.10 增值表新行、里程碑 M9；计划表新增 M14。
2. **核对缺口不能只拿 PRD 当基准**：还应该定期反过来问——「用户最近说过什么、memory 里有什么偏好，是否都已在文档里？」PRD 是基准，但基准本身可能漏项。
3. 题单模式的设计决定（已成文在计划表 14.2/14.3）：
   - **关卡 = 参数集**（音域、白/黑键、允许音程/和弦、旋律长度与速度、节奏型长度与时值 + 题数 + 通过线），**不是抽象难度分**；也不写平行的练习代码，关卡通过 `?level=` 打开普通练习页并钉住参数。
   - **判关在服务端**（按上报轮次与通过线），重复挑战不降级、只抬高最好成绩。
   - 关卡定义在客户端（产品内容），服务端只存结果 —— 单人练习，无作弊动机，换来的是改难度只需改一张表。

## 原因

- 文档是唯一被所有后续工作共享的记忆。对话不是。
- 我当时的做法是"以 PRD 为基准逐条核缺口"，这在 PRD 完整时有效，在 PRD 有漏项时会**系统性地把漏项一直漏下去**。
