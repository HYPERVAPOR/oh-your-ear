# 留了位置，还是被撑高了

登录页要修的问题：错误信息是表单中间一个独立段落，一出现就把卡片撑高约 40px，而卡片外面是居中布局，于是整块内容上下同时弹一下。

修法看起来显然：**那一行始终占位**。`ui/field.tsx` 改成"调用方传了字符串就渲染"（`hint !== undefined`，不做真值判断），并给固定行高：

```tsx
{message !== undefined && (
  <p className={cn('min-h-[18px] text-[13px] leading-[18px]', error ? 'text-error-text' : 'text-muted')}>
    {message}
  </p>
)}
```

量第一轮：初始 / 邮箱不合法 / 改回合法 / 验证码错误 四态都是 **579px** —— 通过。第五态 **597px**。

**差 18px = 正好一行。** 验证码已发送的提示是"验证码已发送。若服务端未配置邮件投递，验证码会打印在服务端日志里"—— 13px 字号在卡片 382px 内容宽里**换行成两行**，占位的 18px 装不下。固定高度说的是"这一行的高度"，不是"这个块的高度"。

改法不是裁字（`truncate` / `line-clamp-1` 会把错误截成看不懂的半句），而是**把文案删短**：那句"打印在服务端日志里"是开发期知识，`docs/deploy.md` 里本来就有，界面上不需要 —— 删到"验证码已发送。"，五态 579px 齐。

**下次**：凡是"用留白换取布局不跳"的地方（消息行、提示行、徽标位、按钮里的读秒文案），**预留的高度和文案的长度是一件事**。写完就量最坏的那一态（最长的那句、双语里更长的那个、320px 宽），别量平均态。中文换行尤其容易漏：同样信息的 zh 往往比 en 短一个词、长一个从句。
