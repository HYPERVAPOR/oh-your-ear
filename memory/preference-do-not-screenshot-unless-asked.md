# 不要主动截图，用户没说就不用

## 约定

**默认不截图。** 改完 UI 直接说改了什么、让用户自己刷新看（给出硬刷新提示）。只有用户**明确要求**时才截图，例如：

- "帮我看看效果" / "截图给我"
- "手机上是什么样"
- 用户看不到环境（比如只有 CI，没有本地浏览器）

## 为什么

1. **重复劳动**：用户在 `localhost:5173` 上本来看得见，而且他明确说过"等我肉眼看完再继续"。我截图 = 同一件事做两遍。
2. **阻塞对话**：`bash` 是同步的，命令不结束我就无法说话。一张截图 = Windows Chrome 冷启动 10~30s + `--virtual-time-budget` + dev server 编译，三张串行就是两三分钟**完全静默**。用户看不到任何进度，观感就是"卡死了"。
3. **有副作用**：被中断的截图命令会把临时的 `apps/web/public/__shot.html` 留在 `public/` 里，而**这个目录会打进构建产物**，必须在提交前删掉。

## 如果确实需要截图

- **一次一张**，不要串行排三张。
- 单次命令给足超时，但**先跟用户说一句"我去截图，约 N 秒"**，别静默。
- 结束后立刻 `rm -f apps/web/public/__shot.html` 并确认。
- 相关工具细节见 `2026-09-18-wsl-headless-verification-via-windows-chrome.md`。

## 同类教训

静默的长等待是同一个毛病：CI 轮询 `gh pr checks` 用 `--watch`（自带输出），别写 `sleep 30` × 20 的死循环。**凡是可能让对话静默超过十几秒的操作，要么先说一声，要么让它自己输出进度。**
