# 只删被点名的那些

用户原话：「删的时候只删被点名的那几样。」

## 犯过的两次

**第一次（热力图）**：用户点名删「连续 N 天 · 最长 M 天」那一行，我顺手把同一附近的其它文案也当「同类噪音」处理了。规则由此而来。

**第二次（账号卡，2026-09-25）**：用户说「不要有单独的 log in 按钮，就给这句话里面的 log in 下划线超链接就行了，只有这一句话」。我把「只有这一句话」读成「连卡片标题一起删」，于是把「账号」标签也去掉了。用户当场发现并指出。

关键是：**PRD 里明明写着「登录后卡片里只有四样东西：标签（账号）、值、动作…」以及「标题不依赖登录」** —— 已有的文档判断和一句口语化的修改要求冲突时，我应该往「少删」的方向理解，或者直接问一句，而不是重写那条判断、还把它从 PRD 里改掉。

## 怎么做

1. 用户点名要删的东西，逐个核对，**不多删一个**；附近「看起来也是同类」的，不动。
2. 当修改要求与已写下的设计/需求判断冲突（PRD、DESIGN、既有注释）时，默认**保守地保留**，并在回复里说明我保留了它、为什么。
3. 真要推翻一条已记录的判断，先说清楚「这会推翻 X」再动手，别顺手改文档把它抹平 —— 改了文档就等于给对方一个「我们本来就这么定的」的假象。
