# 把一份 MIDI 装进网格

用户给了一个路径 `C:\Users\hv\Music\never-gonna-give-you-up.mid`，要求"扩展一个小节、向上扩展几个琴键"。**先解析再动手**这一步救了整轮：那份文件只有 **191 字节**（format 0 / 1 track / division 96，两小节且内容基本是同一句），最高音 F4 —— 而"向上扩展"意味着新素材必须高过 B4。两个推论都对不上，我停下来问，用户确认"是这份"，于是按它做（+12 半音后最高音到 F5，正好需要向上 6 行）。

**教训**：用户嘴里的文件名不等于文件内容。`ls -l` + 解一遍头，比按名字想象便宜得多。库里先前那份是 17549 字节、format 1、division 480 的转写，两者音级集合都对不上（新的没有 A♭/D♭）。

## 装进网格的三条规则

1. **平移而不是改音程。** 算出源音域（这里 C3–F4），整体平移使**最低音落在 `LOW`**（+12），`HIGH` 随之 = 源最高音 + 12（F5 = 77）。18 行、6 个新琴键，音程一个不动。
2. **十六分网格放不下 32 分音符。** 收句是半拍里四个 32 分音，落在格与格之间的那两个**丢掉**（收句读作 F5 → D5 直接进下一小节）。不要为了塞进去把它们挤成同时发声的和弦 —— 那看着像写错了。丢什么、为什么丢，**写进 PRD**。
3. **用脚本生成音符表，不手抄。** 19 个事件 → 量化成 17 个音，`midi/step/length` 由 Python 打印成 TS 片段直接贴进 `roll.ts`。

## 顺带的两条

- **默认内容必须是自己 `normalize` 之后的样子** —— 断言 `normalize(OPENING_PHRASE) === OPENING_PHRASE`，默认和用户拖出来的东西守同一条"同行不重叠"规则。
- **八度不要写死。** 音高轴一到 F5，写死的 `"4"` 就把 F5 念成 `F4 · 698.5 Hz`（名字和自己的频率打架）。从 midi 号算。
