# 三个退信躺在用户收件箱里

用户在 `me@hypervapor.org` 收到几封退信通知：

```
550 Rejected due to high probability of spam
（收件人：async-3-1790337304@ohyourear.test）
```

那是我测「异步发信」时用的三个假地址 —— `ohyourear.test` 是不存在的域名（`.test` 是保留 TLD，没有 MX）。**Spacemail 在自己的出站侧就拒了**，所以没有真的发到互联网上；但退信按**信封发件人**回，而信封发件人就是 `SMTP_FROM`，也就是 `me@hypervapor.org` —— 于是全落进了用户的主邮箱。

## 两条机制值得记住

**一、退信回到信封发件人，不是 From 头。** 这里两者是同一个值（`SMTP_FROM` 同时用作 `MAIL FROM` 和 `From:`），所以退信去哪完全由那个环境变量决定。用 `no-reply@` 之类的地址能把这些噪音从主邮箱移开 —— 前提是那个地址在邮件服务商那边真实存在（很多服务商要求发件人是本域的真实邮箱）。

**二、退信率是发信域名的声誉指标。** 这不是"用户收件箱脏了"的问题，是**自己域名被扣分**的问题。一个新域名（还是自建小站）攒几条 550，后面正常邮件更容易进垃圾箱。所以测试产生的退信要当作真实成本，而不是测试噪音。

## 正确的本地测法（按代价从低到高）

| 目的 | 做法 |
| --- | --- |
| 日常开发、跑流程 | `MAIL_DRIVER=log` —— 验证码打在容器日志里，从日志里捞出来登录 |
| 验 MIME 结构、模板、编码 | 本地起一个假 SMTP 接收端（几十行 socket），api 指向它。私网/link-local 中继允许明文，用户名留空（带用户名连明文连接时 Go 标准库自己会拒：`smtp auth failed: unencrypted connection`） |
| 验真投递 | 临时把 `MAIL_DRIVER` 改 `smtp`，**收件人填自己的真实邮箱** |

**绝不**往不存在的域名、`.test`、`example.com` 这类地址发真邮件 —— 那些域名注定退信，而退信是花钱的。

## 下次

本地 `.env` 里默认 `MAIL_DRIVER=log`，并且把这句话写进注释：改成 `smtp` 的时候，收件人必须是真邮箱。做投递测试之前先问一句"这封信寄不寄得出去" —— 寄不出去的那封会以退信的形式回来找你。
