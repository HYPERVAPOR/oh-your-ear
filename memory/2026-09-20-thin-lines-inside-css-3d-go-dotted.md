# 3D 变换里的细线 = 虚线

给 3D 柱状图画网格时，1–2px 的线在旋转后总断成虚线。原因是两层叠加：

1. **被拍成纹理再重采样**：网格容器的子树自己带了 3D 平移（`translateZ`）却**没有 `transform-style: preserve-3d`**，浏览器就把整棵子树栅格化成一张纹理，再交给 GPU 在旋转后的空间里采样。纹理是一倍分辨率烘出来的，采样位置又是分数像素 → 沿线的覆盖率忽高忽低 → 断续。
2. **细于采样格**：就算不烘焙，1px 的线在旋转（尤其带 perspective）后落在分数像素上，抗锯齿会把覆盖率摊到相邻两像素。覆盖率掉到阈值以下的地方就是"断口"。

和 Unreal 里细几何在 TAA 下闪烁/断裂是同*一族*问题（要素细于采样格），但机制不同：那边是时域抖动 + 没有 MSAA，这边是"先烘焙后重采样"。

## 修法

- **别画发丝线**：在 3D 变换里把线画到 3px 以上（同页面的坐标轴 3px 就一直很实）。
- **保持在 3D 上下文里**：给带 3D 变换的中间层加 `transform-style: preserve-3d`，别让它被拍成纹理。
- 实在不行就别把网格放进 3D（或用斜角更小的视角）。

## 附带教训：本轮的像素测量一直在骗我

- 用**精确色值**统计抗锯齿后的细线 → 严重低估（线被摊成 50% 混合色）。
- 用"单行最长连续段"找水平线 → 找到的是**竖线穿过该行**（相邻行数值几乎相同就是证据）。
- 一次探针跑在**深色**主题下，而阈值按浅色定 → 结论完全反了。
- 结论：**测量前先确认测量对象与判据**（主题、采样分辨率、要测的是哪一类要素）；拿不准时先做一个只改一个变量的对照渲染（比如把旋转归零）再看。
