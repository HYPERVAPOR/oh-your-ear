## 背景

字体变宽会直接影响窄屏布局。等宽字体比原无衬线字体更宽，头部控件（ear badge + 语言 + 主题 + 登录）在 390px 宽度下原本就紧张。

## 经过

- 用 headless Chrome + `public/__shot.html` 注入 localStorage（theme / language / i18nextLng）后用 iframe 定宽截图，验证 390×150 视口。
- 英文 + 等宽下头部仍在单行内（ear badge、English、Dark、Log in），未换行（因为英文标签短）。
- 注意：该截图流程不稳定，中文截图经常生成失败，需要重试。

## 结论

390px 下头部无换行，无需额外处理；但等宽字体带来的溢出风险需在 nav / 按钮等处长文本场景继续留意。

## 原因

`DESIGN.md` 的「一个字体家族」决策让字体度量成为布局风险来源，任何字体变更都应触发一次窄屏头部回归。

## 参考

- 截图命令模式：`chrome.exe --headless=new --window-size=520,200 --virtual-time-budget=8000 --screenshot=...`
- 注入项：`oye-app-storage`（theme/language）、`i18nextLng`
